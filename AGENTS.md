# dstORCH Agent Operating Guide

`dstORCH` is the browser half of the dual-stream transcription pipeline: a Chrome MV3
extension that captures the microphone and a meeting tab separately and streams both to
the `dstDESK` desktop application.

It does **not** own the protocol. `dstDESK` does. This repository consumes a generated
copy and must never define its own.

This guide applies to the whole repository.

## Project Shape

A Chrome extension is not one program. It is several isolated JavaScript environments
that Chrome starts and stops independently; they share no state and communicate only by
message. Almost every structural decision here follows from that.

- `src/background.js` — the **service worker**. Owns the toolbar action and the
  offscreen document's lifetime. Handles no audio. Chrome terminates it when idle, so
  it must hold no state that matters beyond a callback.
- `src/offscreen.html`, `src/offscreen.js` — the **offscreen document**: an invisible
  page where capture and the WebSocket both live.
- `src/capture-worklet.js` — runs on the **audio thread**. Must stay small and
  allocation-light; work done here glitches audio.
- `src/wire.js` — frame and control-message encoding. **Contains no browser APIs**, so
  the same file runs under Node.
- `src/options.html`, `src/options.js` — microphone permission, port, token.
- `src/generated/protocol.js` — generated by `dstDESK`'s build. Never edited, never
  committed.
- `tst/wire-check.mjs` — proves the encoder byte-compatible with the C++ parser.

## Loading And Testing

`src/generated/protocol.js` comes from `dstDESK`'s build, so build `dstDESK` at least
once first.

1. `chrome://extensions` → Developer mode → Load unpacked → this directory.
2. Start `dstDESK`. Match `--port` and `--token` on the options page if used.
3. Open a meeting tab and click the toolbar button. Red badge means capturing.

The first capture opens a page asking for microphone access, then resumes on the tab
you clicked.

Without a browser:

```bash
dstDESK/bin/Release/dstdesk --output out     # terminal 1
node dstORCH/tst/wire-check.mjs --seconds 2  # terminal 2
```

That check imports `src/wire.js` unchanged and drives a real socket, so a wire-format
disagreement can be found and fixed without loading the extension or joining a call. It
exits non-zero on failure. **Run it after any change to `wire.js` or the protocol.**

## Hard Contracts

### One AudioContext

Both streams are fed into a **single** `AudioContext`, and the worklet stamps frames
from `currentFrame` — a counter belonging to the context, not to either node. Two
frames carrying the same index were captured in the same render pass by construction.

This is the decision the entire timing model rests on, and the most expensive one to
reverse. Never create a second context for capture, and never substitute `Date.now()`
or `AudioContext.currentTime` read from the main thread.

### Capture belongs in the offscreen document

MV3 service workers have no DOM and are terminated when idle, so capture cannot live
there. The WebSocket lives beside capture so audio never crosses a `postMessage`
boundary on its way out; at roughly 62 frames a second that would be pure overhead.

### Tab playback stays outside the capture graph

`chrome.tabCapture` silences the tab it captures. The stream is replayed through an
`<audio>` element at its native rate. Routing playback through the 16 kHz capture
context would band-limit the user's actual meeting to 8 kHz for the whole call — the
transcript is not worth degrading the conversation it transcribes.

### A worklet only runs when something pulls it

Web Audio processes a node only when it is connected towards the destination. Each tap
is routed through a zero-gain node so it keeps running without making a sound. Removing
that connection silently stops capture.

### The offscreen document cannot ask for permission

`getUserMedia` there fails immediately with `NotAllowedError` rather than prompting.
Permission is therefore checked first, and the service worker opens the options page —
a context that *can* prompt — when it is missing. Do not move the request back into the
offscreen document.

### Generated constants

`src/generated/protocol.js` is produced by `dstDESK`'s build from `rec/protocol.json`
there. Never hand-edit it, never commit it, and never hardcode a protocol constant
anywhere in this repository.

### `wire.js` stays portable

No `chrome.*`, no DOM, no browser globals. `tst/wire-check.mjs` imports it under Node,
and that check is the only thing standing between a framing mistake and an afternoon of
debugging inside a browser.

## Code Style

- ES modules throughout; `"type": "module"` where a service worker needs it.
- Two-space indentation, semicolons, single quotes.
- `const` by default; `let` only when reassigned.
- Comments explain *why*, especially where a workaround exists because of a Chrome
  constraint. Those constraints are not obvious to a later reader.

## Change Ownership

- `src/background.js` for lifetime, badges, and permission flow.
- `src/offscreen.js` for the audio graph and transport.
- `src/capture-worklet.js` only when the framing or buffering changes.
- `src/wire.js` only alongside a protocol change in `dstDESK`.
- `manifest.json` when a new permission or entry point is genuinely required; every
  added permission is a question a reviewer will ask.

Do not change the protocol here. Change it in `dstDESK/rec/`, regenerate, and verify
with `tst/wire-check.mjs`.

## Testing Expectations

Before claiming a change works, state:

- changed files
- whether `tst/wire-check.mjs` was run and its result
- whether the extension was reloaded and exercised against a real call, or only
  statically checked
- whether the meeting was still audible during capture — this regresses silently
- what the desktop app's session summary reported for frames, gaps and rejects

## Agent Handoff

Static checks alone are not evidence that capture works. A change touching the audio
graph, the permission flow, or the offscreen lifecycle needs a real call before it is
described as working.
