# dstORCH — Verbal

**Verbal** is the Chrome MV3 extension of the dual-stream transcription pipeline;
`dstORCH` is the repository it lives in. It captures two audio streams from a meeting
tab — the local microphone and the tab's own audio — and sends them, kept separate, to
**Kobayashi**, the desktop application in
[`dstDESK`](https://github.com/hrantsp/dstDESK).

Verbal does the talking; Kobayashi listens and writes it down.

The wire protocol is defined by `dstDESK`. This repository consumes a generated copy of
it rather than maintaining its own.

## Loading it

`src/generated/protocol.js` is generated by `dstDESK`'s build and is not committed, so
build `dstDESK` at least once first — see
[`dstOMNI`](https://github.com/hrantsp/dstOMNI) for the workspace layout.

1. Open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked**, and
   select this directory.
2. Start `dstDESK`. If you gave it `--port` or `--token`, set the same values on the
   extension's options page.
3. Open your meeting tab and click the extension's toolbar button. The badge turns red
   while capturing. Click again to stop.

The first time you capture, the extension opens a page and asks for microphone access,
then resumes on the tab you clicked. Capture itself runs in an offscreen document,
which Chrome does not allow to raise a permission prompt — hence the separate page.

Note that Chrome's **"Has access to this site"** setting is unrelated: that governs
page content, while the microphone is a separate permission on the extension's own
origin.

## How it is put together

| File | Role |
|---|---|
| `src/background.js` | Service worker. Owns the toolbar action and the offscreen document's lifetime; handles no audio. |
| `src/offscreen.html`, `src/offscreen.js` | Where capture and the WebSocket live. |
| `src/capture-worklet.js` | Runs on the audio thread; buffers 512 samples and stamps each frame from the shared clock. |
| `src/wire.js` | Frame and control-message encoding. No browser APIs, so it also runs under Node. |
| `src/options.html`, `src/options.js` | Microphone grant, port and token. |

Three decisions explain most of the structure, and all three are recorded with their
alternatives in `dstOMNI/DESIGN.md`:

- **Capture lives in an offscreen document, not the service worker.** MV3 service
  workers have no DOM and are terminated when idle. The WebSocket lives there too, so
  audio never crosses a `postMessage` boundary on its way out.
- **Both streams share one `AudioContext`.** They then share one clock, and ordering
  the two transcripts becomes an integer comparison rather than a drift estimate. This
  is the decision the whole timing model rests on.
- **Captured tab audio is played back separately.** `tabCapture` silences the tab, so
  the stream is replayed at its native rate outside the capture graph — routing it
  through the 16 kHz capture context would band-limit the meeting to 8 kHz for the
  entire call.

## Checking the wire format without Chrome

`tst/wire-check.mjs` imports `src/wire.js` unchanged and drives a real socket against a
running `dstDESK`, so a format disagreement can be found without loading the extension
or joining a call:

```bash
dstDESK/bin/Release/kobayashi --output out     # terminal 1
node dstORCH/tst/wire-check.mjs --seconds 2  # terminal 2
```

It exits non-zero on any failure.
